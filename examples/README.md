# Examples — context-forge run against this repository

The two `context-forge` skills were run against **this repo**, and their output is committed here
as-is. The point is that you can read what the skills actually produce before installing anything.

| File | Produced by | What it is |
|---|---|---|
| [`context-constitution.md`](context-constitution.md) | `context-constitution` | The forged constitution: this repo's Floor / Rules / Norms and its gotchas, each cited to a `path:line` or a commit |
| [`context-constitution-findings.md`](context-constitution-findings.md) | `context-constitution` | The defects the same scan surfaced — a doc-lie and two latent bugs — routed *out* of the constitution for human triage (**CF-N9**) |
| [`context-scrubber-findings.md`](context-scrubber-findings.md) | `context-scrubber` | The scrub report on this repo's own `CLAUDE.md` and `README.md`: which lines cost tokens on every load without changing how an agent behaves, and what to do about each |

The run is configured by [`.agents/context-forge.json`](../.agents/context-forge.json) at the repo
root, which is why the artifacts land here rather than at their default locations.

## What to look at

If you only read one thing, read the **Gotchas & scars** section of the constitution and the
**Should be just-in-time** row of the scrub report. Those are the two hardest classes of finding —
knowledge that exists nowhere but in a commit message, and content that is accurate but wrongly
placed — and they're where the difference between these skills and a summarizer shows up.

Also worth noticing what *isn't* there: most of this repo's rules are already stated in `CLAUDE.md`
or enforced by CI, and those are demoted to one-line entries under `## Pointers` rather than
restated as rules. A constitution that re-indexes what the docs already say is exactly the
low-signal content the other skill exists to delete.

## Honest caveats

- **These are a dated snapshot, not generated output.** They describe the tree as of 2026-07-28,
  on the branch that added them. Line-number citations drift as the code moves — that is the
  normal condition these skills are built for, and `context-constitution refresh` /
  `context-scrubber` re-derive them. Nothing in this directory is regenerated by CI.
- **The behavioral contract and constitution pointer were deliberately not applied.** A normal
  `context-constitution write` also prepends a sentinel-wrapped contract block to the root
  `CLAUDE.md` and adds a pointer to it, because a constitution nothing points at is inert
  (**CF-N11**). That step was skipped here so the example stays purely additive and this repo's
  own `CLAUDE.md` keeps reading as a hand-written file. In a real run you would get both blocks.
- **The scrub report's findings have not been applied.** `context-scrubber` defaults to `scan` —
  it writes the report and trims nothing. The rows it flags in `CLAUDE.md` are still there, which
  is why you can check its work: open `CLAUDE.md:104` and decide for yourself whether that line
  earns its place on every load.
